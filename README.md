# srt-slurm-recipes

This repository is the source of truth for official `srt-slurm` sweep configurations across node counts, models, GPU platforms, and inference frameworks.

The upstream tool is [NVIDIA/srt-slurm](https://github.com/NVIDIA/srt-slurm). Keep benchmark execution logic in that project; keep reusable sweep configuration in this repository.

## Layout

Recipes are organized by benchmark shape:

```text
recipes/
  single-node/
    <model>/
      <gpu>/
        <framework>/
  multi-node/
    <model>/
      <gpu>/
        <framework>/
```

Each leaf directory is reserved for one or more `*.yaml` sweep configs for that exact combination.

Current recipes:

Run `python scripts/update_recipe_table.py` after adding or removing recipe directories,
and `python scripts/update_agentx_table.py` for `agentic/` directories.
The single-node AgentX recipes are generated from the published InferenceX
results with `python scripts/generate_agentx_single_node.py --inferencex <path>`;
edit that script rather than the files it writes, and add `--refresh-points` to
re-query the dashboard API for newly published datapoints.
The same checks are available as a pre-commit hook at `.githooks/pre-commit`.
Enable it for a checkout with `scripts/install_hooks.sh`.

## AgentX

Ported SemiAnalysis InferenceX agentic-coding (`cc-traces-weka`) recipes.

- **Multi-node:** copies of the published InferenceX YAMLs. GB200 / GB300 NVL72
  jobs that the dashboard labels **Single-node aggregate** (one node, a few
  chips, aggregated serving) still live here, because InferenceX published them
  as YAML under `benchmarks/multi_node/` rather than as bash launchers.
- **Single-node:** no published YAML. The published datapoints come from the
  InferenceX dashboard API. This tree is B200 / B300 / H100 / H200 only.

### Requires an InferenceX checkout

These recipes carry the engine configuration only. The client side stays in
InferenceX: `benchmark.command` runs
[`agentic_srt.sh`](https://github.com/SemiAnalysisAI/InferenceX/blob/main/benchmarks/multi_node/agentic_srt.sh)
out of `/infmax-workspace`, which `srtctl` mounts from `INFMAX_WORKSPACE`.
Neither `srt-slurm` nor this repository vendors that stack, so AgentX recipes do
not run without it:

```bash
git clone --recurse-submodules https://github.com/SemiAnalysisAI/InferenceX.git
export INFMAX_WORKSPACE=/shared/path/to/InferenceX
```

`--recurse-submodules` is not optional. `agentic_srt.sh` sources
`benchmarks/benchmark_lib.sh`, which installs the `utils/agentic-benchmark`
requirements and `-e utils/aiperf`, and `utils/aiperf` is a submodule.
`INFMAX_WORKSPACE` is a host path bind-mounted into the container, so it must
resolve on the compute nodes, not just on the login node.

Then dry-run before submitting: it prints the resolved mount table, and flags a
missing `INFMAX_WORKSPACE` rather than letting the job reach exit 127 after the
workers have loaded.

```bash
srtctl dry-run -f <recipe>
srtctl apply -f <recipe>                        # every variant in the file
srtctl apply -f <recipe>:zip_override_conc[0]   # one published concurrency
```

## Running a Sweep

Install `srt-slurm` from upstream, then point `srtctl` at a recipe YAML in this repo:

```bash
git clone https://github.com/NVIDIA/srt-slurm.git
cd srt-slurm
uv pip install -e .

RECIPES_PATH=/path/to/srt-slurm-recipes
FRAMEWORK=<framework>
uv run srtctl dry-run -f "${RECIPES_PATH}/recipes/single-node/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4/B200/${FRAMEWORK}/1k1k.yaml"
uv run srtctl apply -f "${RECIPES_PATH}/recipes/single-node/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4/B200/${FRAMEWORK}/1k1k.yaml" \
  --tags official,NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4,B200,"${FRAMEWORK}"
```

The `dry-run` command should be used before submitting jobs.
